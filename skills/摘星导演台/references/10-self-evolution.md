# 10｜持续学习与进化协议

本技能是「活的」知识库：每次产出一个分镜后，都要把本次发现的**新技法、新爆款机制、新失败模式、新模型行为**沉淀回 `09-case-bank.md` 或对应参考文件。文件即记忆；不做这一步，技能就不会进化。

## 一、复盘闭环（每次交付后必做）

1. **看结果**：成片 / 用户反馈 / 分镜稿是否达到预期？区分「方案错」与「实现错」。
2. **找证据**：哪一镜成功了、哪一镜崩了、哪个写法 Seedance 2.5 没理解、哪个密度掉节奏。
3. **抽象规则**：把单次成败提炼为一条可复用的规则（不要只记「这一句写错了」）。
4. **回写沉淀**：把规则写进对应参考文件；跨题材通用技法写进 `09-case-bank.md`。

## 二、沉淀规则（怎么写、写哪）

- **跨题材通用**（镜头密度、动作完成态、八层公式、光影八要素、运镜选型）：写入 `09-case-bank.md`。
- **单题材专用**（玄幻修炼体系、武侠招式、都市权力潜台词）：写入对应 `05/06` 等参考文件，或在 `09` 标注题材标签。
- **模型行为**（Seedance 2.5 对某类提示词的理解偏差 / 新能力 / 新上限）：写入 `08-seedance25-storyboard.md` 的「模型行为记录」。
- **爆款机制 / 市场结论**：写入 `02-redfruit-design.md` 或 `09-case-bank.md`，标注来源与日期。

## 三、进化触发条件

出现以下任一情况，必须触发一次沉淀：

- 同一类失败出现两次及以上（如某题材连续出现跳轴/超载/动作崩坏）。
- 发现一条新的爆款开场 / 钩子 / 反转机制。
- Seedance 2.5 版本或平台能力更新，改变了单段时长、画幅、参考图或提示词行为。
- 检索到新的高价值开源项目 / 权威资料，带来可复用的导演技法。
- 用户明确反馈某类分镜「无画面感 / 模型不理解 / 团队拍不了」。

## 四、反重复与反漂移

- 新增前先检索目标文件，已有则深化，不另起重复条目。
- 优先「窄修正」而非「加一条万能规则」：只针对本次真实失败补规则，不把偶然偏好写成普遍要求。
- 不覆盖既有结论：除非新证据明确推翻，否则在原条目后追加「更新：日期 + 新结论」。
- 用日期标注新增内容，保留可追溯性（参照 zenstory 的 dated-notes 形态）。

## 五、可进化与不可进化的边界

- **可进化**：技法库、案例库、题材路由、爆款机制、模型行为记录、运镜/光影/台词的具体规则。
- **不可被单次经验推翻**：SKILL.md 的四条铁律（30 秒固定组、组内无时间轴、强画面感、先读剧）是本次任务的结构性约束，只能在用户明确变更后修改。

## 六、交接与连续性

当一次任务被中断或跨对话继续时，先读 SKILL.md → 相关参考 → `09-case-bank.md` 的最近新增，再读项目自己的分镜稿与覆盖表，从当前事实继续，不重新生成已完成的部分。已沉淀的技法与案例是跨会话的长期记忆。
